# قالب گزارش بازگشت به مدیر پروژه

هنگام گزارش واقعی، هر سطر را با واقعیت پر کن؛ اگر اجرا نشده صریحاً NOT_RUN و علت بنویس. مقدار نامعلوم را حدس نزن.

## هویت
- Task IDs و وضعیت:
- Branch / base SHA / candidate SHA:
- PR URL و base branch:
- Production SHA مشاهده‌شده و زمان UTC:
- وضعیت worktree و commitهای مربوط:

## تغییر و دلیل
- مسئله، فایل‌های تغییرکرده و رفتار حاصل:
- دلیل هر تغییر خارج از فهرست اولیه:
- تصمیم‌های نیازمند مالک:

## شواهد
| فرمان یا سناریو | نتیجه PASS / FAIL / NOT_RUN | مسیر artifact یا لینک |
| --- | --- | --- |
| تست متمرکز مرتبط | ثبت نتیجه واقعی | مسیر واقعی |
| ci:quick و ci:contracts | ثبت نتیجه واقعی | مسیر واقعی |
| build و predeploy:smoke | ثبت نتیجه واقعی | مسیر واقعی |
| E2E جستجو و CTA و a11y | ثبت نتیجه واقعی | مسیر واقعی |
| موبایل/دسکتاپ، روشن/تاریک | ثبت نتیجه واقعی | تصاویر قبل/بعد |
| Lighthouse هم‌شرایط | ثبت baseline/candidate/دلتا | JSON هر دو |

## حدود و ادامه
- یافته‌های قطعی / فرضیه‌ها / موارد اندازه‌گیری‌نشده:
- مانع و کوچک‌ترین اقدام لازم:
- آیا GSC داده واقعی داشت؟ بازه و فیلتر:
- آیا تستی قبل از تغییر هم fail بود؟ شاهد baseline:
- MERGED: yes/no
- DEPLOYED: yes/no
- OWNER_VISUAL_APPROVAL: yes/no
- اقدام بعدی پیشنهادی:

هیچ credential، env کامل، فایل کاربر، query حساس یا جزئیات خصوصی analytics در این گزارش عمومی ثبت نشود.
