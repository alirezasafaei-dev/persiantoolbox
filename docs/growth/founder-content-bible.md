## 2. Content Mix

| Persona                    | % of Content | Purpose                                                |
| -------------------------- | ------------ | ------------------------------------------------------ |
| **Rose (رز)**              | 60-70%       | Tool tutorials, how-tos, user-facing demos, engagement |
| **Founder (Alireza)**      | 20-30%       | Mission, build-in-public, technical depth, trust       |
| **Team / Build-in-Public** | 10-20%       | Behind-the-scenes, culture, hiring, open-source        |

### When to Use Founder Content

- Announcing a major feature or milestone
- Sharing a technical deep-dive or architecture decision
- Telling the origin story or mission
- Responding to a community question with depth
- Publishing a year-in-review or roadmap update
- Addressing a controversy, outage, or mistake honestly

### When NOT to Use Founder Content

- Daily tool tips (that's Rose's job)
- Generic social engagement
- Comments or replies (use brand voice)
- Anything requiring fabricated metrics

## 3. Content Pillars

### Pillar 1: Build in Public (40% of founder content)

Behind-the-scenes, shipping updates, technical decisions, honest reflections.

**Topics**:

- "ما این هفته ۳ ابزار جدید ساختیم — بذار بگم چطوری"
- "چرا تصمیم گرفتم OCR فارسی رو از صفر بنویسم"
- "اولین ماه PersianToolbox — اعداد واقعی"
- "این باگ ۳ روز وقت منو گرفت — اینجوری حلش کردم"
- "چرا Next.js انتخاب کردم نه React Native"

**Tone**: Honest, specific, includes failures and numbers.  
**Formula**:

```
Hook (problem/context) → What we did → Why → Result → What's next
```

### Pillar 2: Technical Authority (30% of founder content)

How things work, engineering insights, problem-solving approaches.

**Topics**:

- "چطور OCR فارسی با Tesseract.js کار می‌کنه"
- "چرا local-first برای ما مهم‌تر از cloud‌ه"
- "معماری PersianToolbox — monorepo با ۸۶ ابزار"
- "RTL در وب — چالش‌ها و راه‌حل‌ها"
- "چطور یک ابزار رو از ایده تا production می‌رسونیم"

**Tone**: Educational, assumes technical curiosity but not expertise.  
**Formula**:

```
Concept intro → How it works (simple) → Why it matters → Demo/example → Tool link
```

### Pillar 3: User Success Stories (20% of founder content)

Real user problems solved, testimonials, use cases. Always with permission.

**Topics**:

- "یک کاربر بهم گفت فاکتورساز час تهیه فاکتورش رو از ۲ ساعت به ۱۰ دقیقه رسونده"
- "چطور یک وکیل از ابزار قرارداد ما استفاده می‌کنه"
- "داستان یک فریلنسر که رزومه‌ساز ما کمکش کرد شغل بگیره"

**Tone**: Grateful, specific, never exaggerated.  
**Formula**:

```
User context → Problem they had → How they used the tool → Outcome → Invitation
```

### Pillar 4: Industry Commentary (10% of founder content)

Persian tech ecosystem, tools landscape, trends, opinions.

**Topics**:

- "وضعیت ابزارهای فارسی در ۲۰۲۶"
- "چرا حریم خصوصی برای کاربران ایرانی مهم‌تره"
- "Open source در ایران — فرصت‌ها و چالش‌ها"
- "چالش‌های ساخت ابزار برای RTL"

**Tone**: Thoughtful, opinionated but respectful.  
**Formula**:

```
Observation → Analysis → Opinion → Implication for users → CTA
```

## 4. Voice Guidelines

### Language Rules

| Rule                                    | Example                                                           |
| --------------------------------------- | ----------------------------------------------------------------- |
| Use first person                        | "من این ابزار رو ساختم" (NOT "PersianToolbox این ابزار رو ساخته") |
| Use "ما" for team                       | "تیم ما روی این feature کار کرد"                                  |
| Technical terms in English when natural | "monorepo", "local-first", "OCR", "Tesseract.js"                  |
| Persian numbers for audiences           | "۸۶ ابزار" (NOT "86 ابزار") in captions                           |
| English numbers for technical           | "port 3000", "commit 0c08ed44" in threads                         |

### Tone Spectrum

```
← too casual          ALIREZA SWEET SPOT          too formal →
"سلام بچه‌ها"    "وقتی داشتم این مشکل رو حل می‌کردم..."    "با سلام خدمت کاربران گرامی"
```

### Authentic Voice Examples

**Build-in-public**:

> "وقتی داشتم OCR فارسی رو می‌ساختم، فهمیدم که Tesseract.js به تنهایی برای متن فارسی کافی نیست. مجبور شدم یک preprocessing pipeline بنویسم که مشکلات RTL و نویسه‌های عربی رو حل کنه."

**Technical authority**:

> "یکی از سوالاتی که زیاد می‌پرسن اینه که چرا فایل‌ها رو سرور آپلود نمی‌کنیم. جواب ساده‌ست: حریم خصوصی. وقتی یک فاکتور یا رزومه می‌سازی، اطلاعاتت حساسه. ما تصمیم گرفتم همه چیز توی مرورگر خودت انجام بشه."

**User success**:

> "هفته پیش یک پیام از یک حسابدار دریافت کردم که گفت فاکتورساز ما زمان تهیه فاکتورهاش رو از ۲ ساعت به ۱۰ دقیقه رسونده. این دقیقاً همون دلیلی‌ه که این پروژه رو شروع کردم."

### What Alireza IS NOT

- ❌ Corporate or formal ("با سلام و احترام")
- ❌ Fake-hype or overly enthusiastic ("انقلابی در ابزارهای فارسی!")
- ❌ Condescending or lecture-y ("شما باید یاد بگیرید...")
- ❌ Generic or forgettable ("ما بهترین ابزار رو داریم")
- ❌ Unrelatable or out-of-touch
- ❌ Defensive when criticized

## 5. Content Format Matrix

### Instagram (Founder Account)

| Format                   | Duration/Length | Frequency | Purpose                         |
| ------------------------ | --------------- | --------- | ------------------------------- |
| **Build-in-Public Reel** | 30-60 sec       | 2x/month  | Ship updates, behind-the-scenes |
| **Technical Demo Reel**  | 60-90 sec       | 1x/month  | How something works             |
| **Carousel**             | 8-12 slides     | 2x/month  | Deep-dive walkthroughs          |
| **Story**                | 15 sec max      | Weekly    | Quick updates, polls, community |

#### Instagram Reel Structure (Founder)

```
0-3 sec:   Hook — "وقتی داشتم [context]..."
3-15 sec:  Problem / Context — what was the challenge
15-40 sec: Solution / Process — what we did, how
40-55 sec: Result — numbers, demo, outcome
55-60 sec: CTA — one clear action
```

#### Instagram Carousel Structure (Founder)

```
Slide 1:  Hook title (bold, single sentence)
Slide 2:  Problem statement
Slides 3-7: Steps / insights / data
Slide 8:  Result or takeaway
Slide 9:  CTA + tool link
```

### X (formerly Twitter)

| Format           | Length      | Frequency | Purpose              |
| ---------------- | ----------- | --------- | -------------------- |
| **Thread**       | 5-12 tweets | 1x/week   | Technical deep-dives |
| **Quick Tip**    | 1 tweet     | 2x/week   | Bite-sized insights  |
| **Reply Thread** | 2-5 tweets  | As needed | Community engagement |
| **Poll**         | 4 options   | 1x/month  | Audience insight     |

#### Thread Structure

```
Tweet 1:  Hook — bold claim or question
Tweet 2:  Context — why this matters
Tweets 3-8: The meat — steps, data, insights
Tweet 9:  Result / takeaway
Tweet 10: CTA — tool link or follow prompt
```

### YouTube Shorts

| Format              | Duration  | Frequency | Purpose                |
| ------------------- | --------- | --------- | ---------------------- |
| **Technical Demo**  | 30-60 sec | 2x/month  | Show something working |
| **Quick Explainer** | 60-90 sec | 1x/month  | How a feature works    |
| **Build Montage**   | 30-60 sec | 1x/month  | Speed build, timelapse |

### Telegram

| Format              | Length         | Frequency | Purpose                |
| ------------------- | -------------- | --------- | ---------------------- |
| **Technical Post**  | 500-1000 words | 1x/week   | Deep technical content |
| **Update Post**     | 200-400 words  | 2x/month  | Feature announcements  |
| **Community Reply** | Variable       | As needed | Answer questions       |

## 9. Negative Constraints

### NEVER Do

| Constraint                                       | Reason                     | Example Violation                                |
| ------------------------------------------------ | -------------------------- | ------------------------------------------------ |
| **NEVER fabricate metrics or user numbers**      | Destroys trust             | "۱۰۰,۰۰۰ کاربر فعال" (if not true)               |
| **NEVER claim features that don't exist**        | Legal/ethical risk         | "ما AI داریم" (if no AI features)                |
| **NEVER use corporate marketing language**       | Alienates audience         | "ما پیشرو در صنعت ابزارهای فارسی هستیم"          |
| **NEVER show sensitive user data**               | Privacy violation          | Showing real user documents or info              |
| **NEVER promise timelines without certainty**    | Sets false expectations    | "هفته آینده ۱۰ ابزار جدید میاد"                  |
| **NEVER fabricate lived experiences**            | Authenticity violation     | "وقتی من در شرکت X کار می‌کردم..." (if not true) |
| **NEVER use "من این کار رو کردم" for team work** | Misrepresents contribution | Claiming solo credit for team effort             |
| **NEVER apologize for being Persian/Iranian**    | Identity shame             | "می‌دونم ابزارهای فارسی معمولاً خوب نیستن..."    |

### Allowed Language (Authentic)

| Allowed                                | Example                                        |
| -------------------------------------- | ---------------------------------------------- |
| "من این ابزار رو ساختم..."             | "من این ابزار رو ساختم چون بهش نیاز داشتم"     |
| "وقتی داشتم این مشکل رو حل می‌کردم..." | "وقتی داشتم این مشکل رو حل می‌کردم، فهمیدم..." |
| "تیم ما روی این کار کرد..."            | "تیم ما روی این feature ۲ هفته کار کرد"        |
| "ما تصمیم گرفتیم..."                   | "ما تصمیم گرفتیم local-first باشیم چون..."     |
| "یکی از چالش‌ها..."                    | "یکی از چالش‌ها RTL بود که..."                 |

### Tone Red Lines

- ❌ "ما بهترین ابزار فارسی رو داریم" → ✅ "سعی کردیم ابزاری بسازیم که واقعاً کار کنه"
- ❌ "انقلابی در ابزارهای فارسی" → ✅ "یک قدم کوچک به سمت بهتر شدن"
- ❌ "همه باید از ما استفاده کنن" → ✅ "اگه نیاز داری، امتحان کن"
- ❌ "رقبای ما ضعیف‌ن" → ✅ "ما سعی کردیم یک چیز متفاوت بسازیم"
- ❌ "این feature رو فردا release می‌کنیم" → ✅ "روی این feature کار می‌کنیم"

## 11. Rose vs Alireza — When to Use Which

| Situation                      | Use Rose | Use Alireza              |
| ------------------------------ | -------- | ------------------------ |
| Daily tool tutorial            | ✅       | ❌                       |
| "How to compress PDF"          | ✅       | ❌                       |
| "Why I built PersianToolbox"   | ❌       | ✅                       |
| Technical architecture explain | ❌       | ✅                       |
| "OCR behind the scenes"        | ❌       | ✅                       |
| Quick tip (save this)          | ✅       | ❌                       |
| Origin story                   | ❌       | ✅                       |
| User testimonial               | ✅       | ✅ (with personal touch) |
| Industry commentary            | ❌       | ✅                       |
| Feature announcement           | ✅       | ✅ (for major launches)  |
| Build-in-public update         | ❌       | ✅                       |
| Community engagement           | ✅       | ✅                       |

### Collaboration Rule

Rose and Alireza can coexist in a single content piece:

- Rose introduces the tool: "این ابزار رو ببینید..."
- Alireza explains the why: "من این رو ساختم چون..."

But they should NOT be confused. Each has a clear voice and purpose.
