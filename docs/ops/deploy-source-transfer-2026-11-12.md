# Incremental source transfer repair

Measured incident: the approved PR270 release spent most of its deployment window sending unchanged source files from a GitHub runner over a degraded network path. The receiver had transferred approximately 58 MB of documentation while runtime source directories remained empty. CPU and disk were idle and local synthetic SSH transfer was materially faster; TCP showed substantial out-of-order reception on the runner connection. DNS post-deploy failures are a separate observed issue and are not solved by this patch.

Keep the canonical wrapper and engine. Add rsync --checksum and --copy-dest referencing the current production release as a read-only comparison basis. Checksum comparison is necessary because Git checkouts have different mtimes. Unchanged files are copied locally into the independent candidate directory; changed files still travel over SSH. Use copy-dest rather than hard links so candidate writes cannot alter rollback content. Preserve exclusions, exact release identity, checks, backups, slot verification, traffic switching, retention and rollback.

Verification plan: real rsync fixture for changed-byte count, differing checkout times, independent inodes, previous-file retention and deletion limited to candidate; missing baseline fallback; existing deployment safety/workflow tests, shell syntax, security checks and independent review. No publication until exact-head gates pass and owner explicitly approves this new deployment-wrapper version. Existing PR270 publication remains separately authorized but cannot incorporate unapproved source changes.
